## Status and evidence rules

| State | Meaning |
| --- | --- |
| Implemented | A specific code/configuration artifact exists; this alone proves neither deployment nor correctness. |
| Owner action | Named owner/institution input, authorization, console action or real-device exercise is required. Unknown values remain `REQUIRED`, never invented. |
| Blocked | Missing implementation, access, credentials, licenses, validation or approval prevents completion/activation. |
| Verified | A named check actually ran, with environment, revision, date and result recorded. Documentation or a proposed command is not a passed check. |
| Planned | Required future implementation or acceptance work, not delivered by these skeletons. |

Use separate code-completion, configuration, scientific-validation, device/provider-verification, operational-authorization and store-acceptance records. Never compress them to one green readiness flag. Record evidence as: requirement; artifact/revision; environment; owner; command/manual procedure; expected result; actual result; date; blocker; recovery decision. Never include secrets, passwords, tokens, private keys or unnecessary personal information.

## Binding architecture and safety requirements

### Foundation and PostgreSQL consolidation â€” S02

- Shared modular Express/TypeScript API and independently running persistent workers; follow controller â†’ Zod validation â†’ service conventions, `ah`, `requireAuth`, `validateBody`, `serialize`. Planned modules cover regions, sources, observations, correlation, impact, safety, policy, readiness and mobilization.
- External managed **PostgreSQL 18 with PostGIS** is the target, subject to actual server/extension/TLS/region/pooling/PITR checks. Preserve Prisma 8 migration ownership in `migrations/app/` and synchronize `prisma8/contract.prisma` with the Prisma 7 compatibility schema. Preserve computed extensions; no Accelerate cache dependency for authorization or safety decisions.
- Use PostGIS/GiST, SRID 4326 interchange, geography/projected distances in meters, invalid-geometry/dateline handling; partition sensor/heartbeat history with BRIN and spatial/time indexes. Keep global receipt/dedup keys outside partitions where needed for uniqueness. JSONB/GIN is for bounded metadata, not a substitute for typed lifecycle/security fields.
- Logged jobs/outbox use short `FOR UPDATE SKIP LOCKED` claims, leases, fencing, deadlines, bounded retries/dead letters and replay. External calls are outside transactions. At-least-once execution uses unique business/action/recipient keys; no end-to-end exactly-once promise. `LISTEN/NOTIFY` is only a wake-up hint with dedicated session listeners, polling and cursor recovery.
- Commit and deduplicate bounded sensor ingress before acknowledgement or expensive processing. Urgent evidence/safety workers cannot be starved by feeds, raster work, historical relays or analytics. Use organization quotas, correlation leases/version checks and overlapping time/spatial windows. Stale evidence goes to history, never a fresh alarm.
- Summary/materialized views show freshness; dispatch uses current transactional data. PostgreSQL text search/optional `pg_trgm` suffice; Redis, Kafka, vector databases and `pg_cron` are not requirements. Never use unlogged tables for observations, alerts, jobs or audit. Media stays in object storage; no default raw-audio upload.
- Non-owner runtime roles, no `BYPASSRLS`, transaction-local context and pooled-context reset are required. Use composite ownership constraints, not only application filters. Public hazards and private operational overlays are separate.
- Additive migration, restored-database rehearsal, parity checks, approved legacy-organization/coordinate backfill and duplicate-assignment reconciliation precede production. Cutover requires explicit authorization, verified backups, write freeze/final synchronization. Rollback after new writes requires reconciliation, not switching a URL. No destructive demo seeds.

### Identity, organizations and platform ownership â€” S04/S08

- Firebase ID tokens for native clients, Firebase Admin session cookies for web; verify signature, exact project issuer/audience, expiry, revocation and disabled-user status. No emulator trust in production, arbitrary OAuth access tokens, decoded-only JWTs or second VolunteerOps long-lived JWTs. Web session creation needs recent authentication, CSRF/origin checks and secure HttpOnly cookies.
- PostgreSQL maps immutable unique `(project, UID)` to existing numeric user IDs, and is authoritative for current activity, onboarding, roles, memberships, credentials and permissions on every protected request and sensitive transaction. Custom claims are hints. Identity bootstrap creates at most an unassigned account, not an admin or active workspace.
- Both apps require email/password verification/recovery and Google, Apple, Facebook and Microsoft login. Provider linkage requires authenticated existing and new accounts with recent reauthentication, never email-only linking. Handle Apple private relay, changed email and UID conflicts safely. Use Firebase password flows; never store plaintext passwords.
- Preserve IDs/relations using a controlled migration registry and owner-approved reset/invitation or carefully rehearsed optional import. Argon2 import is not assumed supported by Node; inspect parameters and supported Java Admin tooling first. Make legacy hashes nullable in both schema representations; retire local tokens/cookies/bypasses only at approved cutover and hashes after the recovery window. No demo-account migration or indefinite dual-auth/token guessing.
- Shared Firebase directory plus Identity Platform institution-specific SAML/OIDC; no automatic separate directory per organization. Exact trusted issuer/audience/ACS/redirect/claims and supported SDK/system-browser flows are mandatory. SAML is SP-initiated; Google/Microsoft social is not institutional SSO. Unsupported KMP flow stays blocked; one-use short-lived PKCE/state handoff must preserve assurance and keep tokens out of URLs.
- Require verified email, recent auth and MFA for platform/org admins. Check each organization's allowed method and MFA/SSO evidence on every privileged request, cookie session, switch and mutation; linked-provider presence is not assurance. Missing evidence fails closed. Prefer supported TOTP or explicitly validated institutional MFA evidence.
- Only explicitly granted `TECH_ADMIN` can provision and activate after partnership approval; no first-signup, domain, social-provider, old `SUPER_ADMIN` or request-body authority. `PROVISIONED` and `ACTIVE` workspace state is distinct from domain/SSO readiness and membership admission. Enrollment grants allow only named onboarding steps. Initial admin roles are owner-preauthorized.
- Domain proof uses normalized IDNA/exact labels, no wildcards/public suffix claims or suffix matching; expiring single-use workspace-bound DNS challenges, disputes/revalidation, safe rate-limited discovery and explicit slug/invite for shared domains. Mailbox proof is not institutional control or employment. Owner-approved alternative evidence must be audited.
- Expiring hashed recipient/org/role/issuer/use-bound invitations are atomically accepted. Imports create reviewed drafts/invitations with per-row outcomes, not passwords or silent account links. Public installation, invite links and eligible-domain enrollment never confer automatic admin access. Personal-email volunteers/external coordinators can be invited.
- Logical records include organization/unit/domain/connection, membership/scopes, invitations/join requests, provisioning operations, platform grants, authentication policies, entitlements and immutable audits. Membership unique by org/user; region/unit/function scopes narrow capabilities. Parent labels/domains do not create inherited cross-agency access.
- Scope availability, qualifications, achievements and private notes by membership; maintain minimal shared personal identity. Assign org ownership to missions/deployments/reports/resources/overlays/messages/assistance/audit/reservations/storage. Quarantine ambiguous legacy ownership. Scope workers, recipients, downloads, exports, replay, caches and analytics; reject queued actions from revoked scope. Lock shared responder identity across memberships without leaking private assignment details.
- Sharing is default-deny; named incident/resource grants are expiring and bilateral, with consent where needed and one lead deployment owner. Suspension immediately denies PostgreSQL access while external revocation retries; stop private streams/delivery/admission, reconcile pending jobs and hand over missions/assistance without erasing evidence or unrelated memberships.
- Same admin app, visibly separate Platform/Organization contexts. Guarded out-of-band one-time bootstrap requires verified chosen UID/MFA and empty-grant protection; no public bootstrap route/default credentials. Protect last owner; audit break-glass, step-up, impact/reason and key rotation. Platform support access is time-bound, visible and audited, never silent impersonation or database-superuser access.
- Global disable/delete is tech-admin-only, distinct from membership removal and verified self-service privacy deletion (apps plus web entry point, recent reauth, retention/hold handling). Feature controls configure implemented functionality with preview/version/rollback/audit, not arbitrary SQL/source execution or scientific certification. Provisioning uses idempotent operations/outbox/reconciliation because Firebase, email and PG are not one transaction.
