# Private object storage

The current deployment request authorizes a new private S3-compatible bucket. PostgreSQL owns the object metadata and authorization; the bucket holds bytes. This integration does not turn the database into an object store and does not grant access based on legacy global roles.

## Implemented boundary

`src/modules/scoped-storage/` exposes private attachments owned by the uploader within an active organization and region. `stored_objects` has composite foreign keys to the organization's region and uploader membership, database row-level security, and size/completion checks. Every request rechecks the current Firebase session, organization, membership and region. Organization administrators cannot implicitly download another member's attachment. Sharing with a mission/report or reviewer requires a future explicit resource-access contract.

The old `/api/storage` endpoints remain behind `TENANT_MIGRATION_REQUIRED`.

Accepted media types: JPEG, PNG, WebP, PDF and plain text. Maximum size: 10 MiB. Raw audio, HTML and SVG are rejected. Uploads require the full file's base64 SHA-256 digest. Names are sanitized and object keys are generated by the backend; clients cannot select an existing key or a bucket.

Per uploader, organization and region: 10 unexpired pending intents, 100 new intents per rolling day, and 250 MiB total reserved/completed metadata. Expired intents continue reserving bytes until an operator reconciles possible orphan objects. This prevents repeatedly expiring uploads from bypassing the storage quota.

## Runtime configuration

Supply server-side `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, and `S3_SECRET_ACCESS_KEY`. `S3_ENDPOINT` must be a clean HTTPS URL. Set `S3_FORCE_PATH_STYLE=true` when required by the chosen compatible service. Never bundle these credentials in the admin or volunteer apps.

Use private bucket access and credentials restricted to object PUT/GET/HEAD for this bucket; no public/anonymous reads or bucket administration. Runtime PostgreSQL grants are `SELECT, INSERT` on `public.stored_objects` and `UPDATE (state, completed_at, etag, version_id)` only. The runtime must not own the table or inherit a privileged role. Migrations run separately with the owner connection.

Bucket CORS must list the actual HTTPS admin, volunteer and backend portal origins. Permit PUT/GET/HEAD, headers `content-type`, `x-amz-checksum-sha256`, `if-none-match`, and `if-match`; expose `ETag` if clients need it. Do not use wildcard origins as a substitute for configuring these sites. Browser fetch calculates Content-Length from the actual file; it must match the declared `byte_size`.

## API flow

All paths below start with `/api/organizations/:orgId/regions/:regionId/storage`. Use a current Firebase bearer identity or the backend session cookie. Cookie mutations require the normal approved Origin and `X-Requested-With` header.

1. Calculate SHA-256 over the complete file before upload.
2. `POST /upload-intents` with `{ "file_name": "photo.jpg", "content_type": "image/jpeg", "byte_size": 1234, "checksum_sha256": "<base64 SHA-256>" }`. Save the returned `object_id`. Response includes `upload_url`, method `PUT`, required `headers`, 300-second URL expiry and a 15-minute completion deadline.
3. PUT the exact file bytes to `upload_url` with the returned headers. Do not attach Firebase credentials to this bucket request. The signature binds length, type, SHA-256 and `If-None-Match: *`. A repeated successful upload can return 412; call completion to determine whether the original object is already stored.
4. `POST /:objectId/complete` with `{}`. The backend verifies HEAD size/type/ETag. If the provider omits the stored SHA-256, it reads a bounded stream pinned to the HEAD ETag/version and hashes it. Only exact matches become `READY`. Membership is checked again after storage I/O; a concurrent suspension prevents completion. Repeated successful completion is idempotent.
5. `POST /:objectId/download` with `{}`. Only the original uploader can request this while still authorized in the region. Fetch the returned `download_url` with its required `headers`, then save the resulting Blob under `file_name`. This URL lasts 60 seconds, is pinned to the verified ETag/version, forces attachment disposition and octet-stream type, and disables caching. A raw anchor cannot supply the required `If-Match` header; use fetch.

Issuing, completing and downloading an object write organization audit records with object IDs and sizes, never signed URLs or credentials. Signed URLs remain bearer capabilities until their short expiry; membership revocation blocks new URL issuance, not an already issued URL at the bucket.

## Verification and remaining operations

Automated tests cover signed headers, checksum fallback, stream size bounds, spoofed type/size/digest, missing objects, sanitized errors, PostgreSQL RLS, cross-organization and region denial, uploader ownership, composite foreign keys, pending quotas, expiry, idempotent completion and revocation during verification. Live-provider PUT/HEAD/GET and negative anonymous-access checks must also pass before claiming the deployed bucket works.

This is a private attachment boundary. Content scanning, content-type sniffing, attachment-to-report sharing, deletion/legal holds, automated orphan reconciliation and bucket backup/restore are not yet implemented. Verified digest means bytes match the intent; it is not a malware verdict. Downloads are forced attachments rather than embedded previews. Configure capacity alerts, private backups and credential rotation on the actual provider, and rehearse database metadata and object recovery together. Do not apply a bucket lifecycle rule that silently deletes completed attachments still referenced in PostgreSQL.

Protocol references: [S3 PutObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html), [S3 HeadObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html).
